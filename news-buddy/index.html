Engineering

PHP shares mitigation for a new RCE vulnerability with no patch — CVE-2026-115560via BleepingComputer relay

A third PHP flaw, disclosed Friday — distinct from PHP2Shell: CVE-2026-115560 is exploitable only when an app sets session.serialize_handler to php_binary or php_serialize, then switches it to php at runtime before session_start(), with upload progress enabled. The PHP team calls the combination unlikely, is handling it in the regular release cycle, and advises session.upload_progress.enabled=0 as mitigation. VirusTotal estimates 5.1M PHP hosts exposed online.

The storage aisle, Oct. 24: Synology shipped updated PHP packages via Package Center; QNAP confirmed affected products but gave no timeline; TerraMaster said Oct. 22 it was investigating; Ugreen and Asustor are working on fixes with no dates, per TechRadar’s reporting. Attackers recorded attempts on Oct. 17, four days before disclosure — the gap is the story.

Tech Insider

Critical PHP security update 8.5.12 and 8.4.27: what website owners must do nowsecurity journal

The patch guide, Saturday edition: PHP’s Oct. 21 emergency releases fix CVE-2026-109618 and CVE-2026-109619, both unauthenticated RCE, in 8.5.12, 8.4.27, 8.3.36 and 8.2.35. No complete workaround exists — updating is the only safe fix. Check for compromise first: unusual multipart requests followed by memory-limit errors, repeated PHP worker 500s, oversized PHPSESSID cookies.
