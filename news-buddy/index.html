Binance reopens the doors: phased withdrawals begin, bitcoin first, with ~95% of the $6.3 billion theft replaced from the exchange’s own money

CoinDesk, Nov. 1: Binance resumed withdrawals Sunday for bitcoin and assets on 15 other blockchains, the first window running 06:00-09:00 UTC, with further re-openings contingent on per-network security and stability checks. The exchange says it has replaced about 95% of the stolen assets — up from 90% Saturday — using company funds, and that BTC, ETH, USDT, BNB, SOL, USDC, XRP, USD1, RLUSD and ZEC balances are fully backed. Bitcoin traded near $77,895. TRM Labs puts the stolen bitcoin at 18,270 BTC (about $1.47 billion); the FBI has attributed the Oct. 29 theft to North Korea’s TraderTraitor. A full proof-of-reserves is expected by Nov. 3. CZ’s confirmation was three words: ’BTC withdrawal is live.’

Engineering

DeepSeek open-sources its Super-agent: an MIT-licensed prototype that takes work requests from GitHub and answers with pull requests

DeepSeek’s Harness team published dsh-superagent-prototype on Oct. 31: a proactive coding agent for one GitHub repository that listens to GitHub (and optionally Feishu), opens a work item when an authorized person asks, works in its own session and directory, and replies in the original conversation — potentially with a pull request. In the team’s synthetic test (about 300 simulated messages, roughly 20 work requests), half the tasks finished within 12.4 minutes and 95% within 15.7, against 29.5 minutes at the 95th percentile for a single-session setup — at higher cached-token cost. The repo passed 4,100 stars by Sunday morning. The catch is in the design: workers execute commands under the operator’s account without per-action approval, so the README prescribes a dedicated agent GitHub account, a short authorized-people list and blocked commands. Research prototype, not production software — the public code differs from the internal system.

Asia Daily

GitHub previews an npm firewall: block malicious and too-fresh packages at install time, before the agent or the CI runner pulls them

The Hacker News, Oct. 29: GitHub’s package firewall, in public preview for Enterprise Cloud, sits between endpoints or internal registries and upstream repositories, inspecting metadata and downloads against the GitHub Advisory Database — blocking known malware, blocking by vulnerability severity, and enforcing a cooldown (minimum package age, 1-365 days, default 1) so brand-new releases can’t be installed until scanners have had their look. The timing is the point: AI agents and CI runners now install dependencies automatically to complete tasks. Rust 1.100, due Nov. 12, readies the same idea for crates.

The Hacker News

Fix the CodeQL alert where you code: GitHub’s Copilot app security extension turns scanning alerts into reviewed local fixessingle-author walkthrough

In public preview since Oct. 28, the security extension puts open code-scanning alerts, sorted by severity, in a Security canvas beside the Copilot agent session; Explain and Fix run on the session’s own agent and model, and every fix stays in the local working copy until a human reviews and pushes — the alert closes only after a rescan. The design target is the unglamorous reason alerts pile up: the hop between github.com, the editor and rebuilt context. Enterprise controls and AI-credit costs are part of the write-up.
