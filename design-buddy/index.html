The design brief

The source of truth, in full — no login required. Same text as the GitHub copy.

1 · The bar

Every buddy homepage is measured against one standard: craftsmanship as the differentiator. Dave built his career on the Apple principle that a handcrafted, delightful product wins. His pages should feel like they were made by someone who cares — because they were.

Taste line: classic over clever. Ship what Dave praised. Restraint beats novelty.

A homepage is a tool he opens daily, not a portfolio piece — clarity first, personality second.

2 · Non-negotiables the ship checklist

  1. Dark AND light mode. prefers-color-scheme: dark, color-scheme: light dark. Light-only = not done. No exceptions.
  2. Living page. Update when the underlying data changes — stale pages erode trust. Bake a “Last refreshed YYYY-MM-DD” stamp in the footer and mean it.
  3. Brain-dump box. Every homepage gets one: textarea + “Dump it” (Cmd/Ctrl+Enter), appending timestamped entries to docs/ingest.md in the buddy’s repo via the GitHub API. Pattern: docs/dumpbox-snippet.html in the dashboard repo. Set data-buddy-id, resolve the repo via ../buddies.json (never hardcode a repo name), keep dark + light working.
  4. Every document gets its link. Any doc named on the page gets a clickable inline link with a friendly name — never a bare URL, never “go hunt for it.”
  5. Custom pages own their markup. If you hand-design a page, delete the <!-- BUDDY-BASIC-TEMPLATE --> marker so the daily template rebuild never overwrites it.
  6. No placeholder copy. If a section has nothing real to say yet, say so honestly — never lorem ipsum, never invented data.

4 · Components

The recurring pieces, with the class names the reference page uses — each one live in the Components gallery above:

  • status-pill — one-line state under the headline.
  • mission — the buddy’s job in 2–3 sentences; a boundary line for scope limits.
  • attention-card — .card with a left accent border; one per item needing Dave’s tap; always carries the link or action.
  • stat blocks — a row of 3–4 numbers saying what this buddy tracks.
  • dumpbox — the brain-dump pattern (§2.3).
  • link rows — .links ghost buttons: brief, repo, dashboard.
  • last-refreshed stamp — footer line, baked date, updated on every content change.

5 · Taste, concretely

  • One accent color per page. Chips, pills, markers — all from --accent.
  • Hairlines over shadows; one shadow depth, max.
  • Motion: subtle and purposeful (a 150ms hover lift, a pulse on the status dot). Nothing moves without a reason.
  • Emoji: the buddy icon in the headline, functional icons in cards — not decoration confetti.
  • Write like a person: short sentences, no jargon, no “leverage.”

6 · Feedback loop

Design feedback — Dave’s or a thread’s — has one inbox: the feedback box on the Design Buddy homepage, which appends to docs/feedback.md in davedellaquila/design-buddy. Threads can also route feedback through the main chat to the Design Buddy thread. Design Buddy triages each entry: fold it into this brief and the system, or close it with a note. Nothing evaporates.

Scope note: this loop is for the buddy system’s design. Feedback to outside parties belongs to Feedback Buddy.

7 · Before you ship the taste test

  • Both themes readable, no washed-out text on either.
  • Dump box writes a real entry to the repo.
  • Every named document has its inline link.
  • No BUDDY-BASIC-TEMPLATE marker on custom pages.
  • Looks right at phone, tablet, and desktop widths — no broken layouts, no awkward stretching, no horizontal scroll at any size.
  • A stranger understands what the buddy does in 10 seconds.
  • Classic over clever.
